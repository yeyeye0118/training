### 2\.1 分区、引导和空间分配



一块硬盘可以划成多个独立区域，这些区域叫“分区”。Windows 的 `C:` 盘通常是其中一个分区；电脑上还可能有较小的 EFI 系统分区和恢复分区。“引导”是开机时电脑通过启动程序找到并加载操作系统的过程，EFI 系统分区存放相关启动文件；装好双系统后，引导菜单用于选择进入 Windows 还是 Ubuntu。EFI 系统分区不是给 Ubuntu 存软件和作业的空间，不要删除或格式化 Windows、EFI、恢复分区。



Ubuntu 不是作为一个文件夹“塞进 C 盘”。选择 `alongside` 并装时，安装器会在条件允许的情况下缩小可调整的 Windows 分区，腾出尚未分给任何系统的空间，再在这块空间里建立 Ubuntu 自己的分区并安装系统。结果是 Windows 分区变小、Ubuntu 得到独立空间；正常流程会保留 Windows 原有文件，但调整分区仍有数据丢失风险，在安装器最终确认改动前要核对两边的容量。



本组要求**至少给 Ubuntu 分配 80 GB，建议 120 GB 及以上**，这是电脑内置硬盘上的空间，不是制作启动盘的 8/16 GB U 盘。在 Windows 的“此电脑”中先看目标硬盘还剩多少可用空间，并给 Windows 留出日常使用空间；安装时选择第 3\.4 节的 `alongside` 选项，在分配界面按硬盘容量核对目标硬盘，给 Ubuntu 分配上述空间。如果安装器显示实际可分配空间不足 80 GB，就停止安装，不要强行改动已有分区。调整分区前，先把重要文件备份到另一块外置硬盘或云盘。



### 2\.2 检查 Windows 磁盘加密



在 Windows 中搜索“管理 BitLocker”，也检查“设置 → 隐私和安全性 → 设备加密”（不同 Windows 版本的入口可能不同）。有些电脑会自动启用设备加密，即使你没有手动设置过。如果发现加密已启用，安装前先按[微软的说明](https://support.microsoft.com/en-us/windows/security/encryption/find-your-bitlocker-recovery-key)找到 Windows 的 48 位恢复密钥，并把它保存到电脑之外、自己能找回的安全位置；不要把密钥发给别人或输入到 AI 对话中。更改启动或固件设置后，Windows 有可能要求输入这把密钥。



如果准备与 Ubuntu 共用的 Windows 磁盘启用了 BitLocker 或设备加密，安装器可能无法安全识别 Windows 分区。此时不要继续安装，更不要改选 `Erase disk`。先回到 Windows，按照 [Ubuntu 官方的 BitLocker 处理说明](https://ubuntu.com/desktop/docs/en/latest/how-to/turn-off-bitlocker-in-windows/)关闭加密，等待解密完成；随后重启进入 Windows，确认文件仍能正常打开，再重新从 U 盘启动。关闭加密会降低 Windows 数据保护，且部分 Windows 版本可能无法重新开启；如果不能确认加密状态、找不到恢复密钥或无法关闭加密，就先暂停双系统安装。



## 3 安装 Ubuntu



Ubuntu 是电脑的操作系统，ROS 2 是安装在 Ubuntu 上的机器人开发软件。ROS 2 也有不同版本，不能随意混装：本教程中，[Ubuntu 22\.04 对应 ROS 2 Humble](https://discourse.openrobotics.org/t/ros-2-humble-hawksbill-released/25729)，[Ubuntu 24\.04 对应 ROS 2 Jazzy](https://discourse.openrobotics.org/t/ros-2-jazzy-jalisco-released/37862)。两个组合都可以用于本组培训，但后面安装 ROS 时要选与自己 Ubuntu 版本对应的命令。



我们的培训默认选择 Ubuntu 22\.04\.5 Desktop 64 位。使用 Intel Core Ultra 9 第二代等较新平台的电脑，比较可能在 22\.04 的试用系统中遇到无法正常启动、屏幕显示异常、Wi\-Fi 或触控板不可用等问题；[Ubuntu 24\.04 已补充对这类平台的支持](https://documentation.ubuntu.com/release-notes/24.04/2/)。如果遇到这些情况，改用 24\.04 的 U 盘试用，确认关键硬件正常后安装 24\.04，第 6 节再安装 Jazzy。已经安装 Ubuntu 22\.04 或 24\.04、且使用正常的同学，直接跳到第 3\.5 节。



### 3\.1 下载镜像



1. 打开[清华大学镜像站的 Ubuntu 22\.04 镜像目录](https://mirrors.tuna.tsinghua.edu.cn/ubuntu-releases/22.04/)。

2. 下载 `ubuntu-22.04.5-desktop-amd64.iso`。不要下载 `server`、`torrent` 或文件名不以 `.iso` 结尾的文件。

    

选择 24\.04 的同学改用[清华大学镜像站的 Ubuntu 24\.04 镜像目录](https://mirrors.tuna.tsinghua.edu.cn/ubuntu-releases/24.04/)，下载 `ubuntu-24.04.5.1-desktop-amd64.iso`；后续制作 U 盘时选择自己下载的这一份镜像。



### 3\.2 制作启动 U 盘



在 Windows 上使用 Rufus：



1. 打开 [Rufus 官网](https://rufus.ie/)，在“下载”区域选择最新版 Rufus，下载 `.exe` 文件。Rufus 无需安装，双击下载的文件即可运行；Windows 弹出权限提示时允许其运行。

2. 插入准备制作启动盘的 U 盘。在 Rufus 的“设备”栏选中这个 U 盘，核对名称和容量；如果列表中有多个设备，先确认目标 U 盘是哪一个。

3. 在“引导类型选择”旁点击“选择”，打开第 3\.1 节下载的 Ubuntu `.iso` 文件。如果按钮显示“下载”，点击旁边的小箭头切换为“选择”。

4. 其他选项先保持 Rufus 自动填入的值。点击“开始”；如果出现 ISOHybrid 提示，选择“以 ISO 镜像模式写入”。若提示下载写入所需的附加文件，选择“是”。

5. Rufus 会提示清空目标 U 盘。再次核对“设备”栏，确认选中的是 U 盘后点击“确定”。等状态显示“准备就绪”，点击“关闭”并安全弹出 U 盘。

    

已经使用 Ubuntu 的电脑可打开“磁盘”应用，选择目标 U 盘，通过菜单中的“还原磁盘映像”选择下载的 ISO，确认目标设备后开始写入，完成后弹出 U 盘。



### 3\.3 先试用再安装



电脑开机时会按“启动顺序”查找系统：通常先从内置硬盘上的 `Windows Boot Manager` 启动，因此会直接进入 Windows。“从 U 盘启动”是让电脑在这一次开机时读取第 3\.2 节制作的 Ubuntu 启动 U 盘，进入 U 盘上的试用系统和安装程序。现在这样做，是为了先确认 Ubuntu 能在这台电脑上正常运行，再决定是否安装到硬盘。



这里要找的是**一次性启动菜单**（可能显示 `Boot Menu`、`Boot Device` 或 `Select Boot Option`），而不是 **BIOS/UEFI 设置界面**。启动菜单通常是一张可启动设备列表，可能同时列出 `Windows Boot Manager` 和 `UEFI: U 盘品牌`；选择 U 盘只影响这次开机。BIOS/UEFI 设置界面通常有 `Main`、`Advanced`、`Boot`、`Security` 等多个页面，其中的启动顺序设置可能长期生效；本教程不需要修改它。



1. 把制作好的 U 盘插在电脑上，在 Windows 中点击“重启”。出现电脑品牌标志时，按这台电脑的**启动菜单键**。常见按键有 `F12`、`Esc`、`F10`，但各品牌不同；`F2` 在不少电脑上进入的是 BIOS/UEFI 设置。以开机画面提示或电脑厂商的说明为准，不要盲目反复尝试。

2. 如果看到设备列表，选名称包含 U 盘品牌的项目，优先选带 `UEFI:` 的 U 盘项目，然后按 `Enter`。不要选 `Windows Boot Manager`，那会再次进入 Windows。若列表中没有 U 盘，检查 U 盘是否插稳，换一个 USB 接口后重启，再进入启动菜单。

3. 如果看到的是 BIOS/UEFI 设置界面，不要更改 `Boot Priority`、`Boot Order` 或其他设置。选择“不保存退出”（可能显示 `Exit Without Saving` 或类似文字），重新启动后再使用正确的启动菜单键。

4. 看到 Ubuntu 的启动界面后，如有 `Try or Install Ubuntu`，先选择它；选择 `English`，再选择 `Try Ubuntu`。24\.04 安装器的页面顺序可能不同，但同样先进入试用桌面。这会运行 U 盘上的试用系统，暂不把 Ubuntu 安装到硬盘。进入桌面后检查：

    

- 用可用的 Wi\-Fi、有线网络或手机热点能打开网页

- 屏幕分辨率与缩放正常

- 键盘、触控板或鼠标正常

    

屏幕、输入设备和至少一种网络连接方式都正常后，打开试用桌面上的 `Install Ubuntu`，继续第 3\.4 节。如果没有可用网络可以测试，先确认装好系统后能通过有线网络或手机 USB 共享网络联网；否则暂停安装。任一关键硬件不可用时，关闭试用系统、拔出 U 盘并重新启动，先查看电脑厂商的 Linux 驱动说明；确认问题解决后再安装。



### 3\.4 执行安装



1. 在安装器中选择 `English`（系统语言）和 `Install Ubuntu`；24\.04 的页面顺序与 22\.04 略有不同，按这两个选项的含义操作。后续如果再次要求选择系统语言，仍选 `English`；键盘布局按实际键盘选择，它与系统语言不是一回事。有稳定网络时可以连接，并允许安装第三方驱动和媒体格式；如果校园网认证或下载更新一直卡住，可以跳过联网和“安装时下载更新”，先完成系统安装。进入桌面后再联网，执行第 3\.5 节的系统更新和第 3\.6 节的驱动安装。选英文系统语言后，首次登录生成的用户目录通常为 `~/Downloads`、`~/Documents` 等英文名称，才能直接使用本教程后面的目录命令。

2. 需要保留 Windows 时，选择安装器提供的 `Install Ubuntu alongside Windows Boot Manager`（文字可能略有不同，但必须包含 `alongside`）。如果界面只出现 `Erase disk and install Ubuntu` 或 `Something else`，退出安装器并返回 `Try Ubuntu`。如果安装器提示 BitLocker、Intel RST/VMD，或看不到内置硬盘，也先退出。不要直接在 BIOS/UEFI 中关闭 VMD、切换 AHCI；这可能导致 Windows 无法启动。先核对第 2\.2 节，并阅读 [Ubuntu 官方的 Intel RST 说明](https://ubuntu.com/desktop/docs/en/latest/reference/intel-rst-during-ubuntu-installation/) 后，再决定如何处理。

3. 用户名使用小写英文，主机名建议使用 `venom-姓名拼音`，例如 `venom-zhangsan`。不要在用户名和主机名中使用中文或空格。

4. 安装完成后按提示重启并拔出 U 盘。第一次登录后按 `Ctrl Alt T` 打开终端，检查系统。第一条命令应显示你安装的 Ubuntu 22\.04 或 24\.04，第二条命令应输出 `x86_64`。

    

```Bash
lsb_release -ds
uname -m
```



### 3\.5 配置 Ubuntu 软件源



先运行下面的命令：22\.04 应输出 `jammy`，24\.04 应输出 `noble`。如果都不是，先不要继续。



```Bash
lsb_release -sc
```



**Ubuntu 22\.04** 执行下面的命令。它会备份原有软件源，把普通软件包和更新切换到清华镜像；安全更新仍保留 Ubuntu 官方源，以免镜像同步延迟影响安全更新。



```Bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.before-tuna
sudo tee /etc/apt/sources.list >/dev/null <<'EOF'
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-updates main restricted universe multiverse
deb https://mirrors.tuna.tsinghua.edu.cn/ubuntu/ jammy-backports main restricted universe multiverse
deb http://security.ubuntu.com/ubuntu/ jammy-security main restricted universe multiverse
EOF
sudo apt update
sudo apt upgrade -y
sudo reboot
```



**Ubuntu 24\.04** 只执行下面这一组。它会先检查系统自带的软件源文件：如果存在，备份后切换到清华镜像；如果不存在，保留现有软件源并继续更新。



```Bash
if [ -f /etc/apt/sources.list.d/ubuntu.sources ]; then
  sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.before-tuna
  sudo tee /etc/apt/sources.list.d/ubuntu.sources >/dev/null <<'EOF'
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: http://security.ubuntu.com/ubuntu/
Suites: noble-security
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF
else
  echo '未找到 ubuntu.sources，保留现有软件源'
fi
sudo apt update
sudo apt upgrade -y
sudo reboot
```



两组命令中的 `EOF` 都要一起复制，并单独占一行；它是配置内容的结束标记。只执行与你的系统版本对应的一组，重启后继续第 3\.6 节或第 4 节。



### 3\.6 NVIDIA 显卡



打开 `Software and Updates`，进入 `Additional Drivers`，选择系统标记为 `recommended` 的驱动并重启。没有 NVIDIA 显卡的同学跳过本节。优先使用 Ubuntu 提供的驱动包，不要直接运行从 NVIDIA 官网下载的 `.run` 安装文件；Ubuntu 推荐使用 `Additional Drivers` 或 `ubuntu-drivers` 管理驱动。



## 4 安装 C\+\+ 工具链和 Git



以下命令逐行执行。终端输入 `sudo` 密码时不会显示星号，这是正常现象；输入完成后按 Enter。在终端中复制、粘贴通常分别使用 `Ctrl + Shift + C` 和 `Ctrl + Shift + V`；`Ctrl + C` 用于中断正在运行的命令。



```Bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build gdb clang-format pkg-config git curl wget unzip python3-pip python3-venv
```



检查安装结果。版本号可能随系统更新变化，只要每条命令都能输出版本且没有 `command not found` 即可。



```Bash
g++ --version
cmake --version
ninja --version
gdb --version
git --version
python3 --version
```



配置 Git 身份。将示例中的英文姓名和邮箱替换为自己的信息，邮箱建议与代码托管账号一致。



```Bash
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
git config --global init.defaultBranch main
git config --global --list
```



## 5 安装 Visual Studio Code



1. 打开 [VS Code 官方 Linux 安装页](https://code.visualstudio.com/docs/setup/linux)，下载 Debian 或 Ubuntu 对应的 64 位 deb 包。

2. 打开终端进入下载目录，再安装刚下载的 deb 包。若目录中有多个安装包，先删除旧包或把通配符改为完整文件名。

    

```Bash
cd ~/Downloads
sudo apt install ./code_*.deb
```



安装四个扩展。前三个为必装，ROS 扩展用于识别常见 ROS 文件。



```Bash
code --install-extension ms-vscode.cpptools
code --install-extension ms-vscode.cmake-tools
code --install-extension ms-python.python
code --install-extension ms-iot.vscode-ros
```



检查 VS Code 命令，并从终端打开 C\+\+ 示例目录。



```Bash
code --version
mkdir -p ~/venom_cpp_hello
cd ~/venom_cpp_hello
code .
```



### 5\.1 验证 C\+\+ 编译



在 `~/venom_cpp_hello` 中新建 `hello.cpp`，写入以下内容并保存：



```C++
#include <iostream>

int main() {
    std::cout << "Venom C++ environment OK\n";
    return 0;

```



回到终端编译并运行。应看到 `Venom C++ environment OK`，编译阶段不应出现错误。



```Bash
cd ~/venom_cpp_hello

```



## 6 安装 ROS 2



先完成第 3\.5 节的系统更新并重启，再确认版本：22\.04 输出 `jammy`，安装 Humble；24\.04 输出 `noble`，安装 Jazzy。如果输出其他内容，不要继续。



```Bash
lsb_release -sc
```



### 6\.1 添加清华 ROS 2 软件源



下面的命令对 22\.04 和 24\.04 通用。它会根据系统版本自动写入 `jammy` 或 `noble`，添加清华镜像站的 ROS 软件源；如果下载密钥失败，不要继续。



```Bash
sudo apt install -y curl gnupg
curl -fL https://mirrors.tuna.tsinghua.edu.cn/rosdistro/ros.key -o /tmp/ros.key
gpg --dearmor --yes --output /tmp/ros-archive-keyring.gpg /tmp/ros.key
sudo install -m 644 /tmp/ros-archive-keyring.gpg /usr/share/keyrings/ros-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu $(lsb_release -sc) main" | sudo tee /etc/apt/sources.list.d/ros2.list >/dev/null
sudo apt update
```



### 6\.2 安装 ROS 2 桌面版和开发工具



22\.04 执行：



```Bash
sudo apt install -y ros-humble-desktop ros-dev-tools
```



24\.04 执行：



```Bash
sudo apt install -y ros-jazzy-desktop ros-dev-tools
```



配置 `rosdep` 使用清华镜像。下列命令会下载镜像站提供的源列表，并把镜像地址写入 Bash 配置，供以后执行 `rosdep update` 使用。



```Bash
sudo mkdir -p /etc/ros/rosdep/sources.list.d
sudo curl -fL https://mirrors.tuna.tsinghua.edu.cn/github-raw/ros/rosdistro/master/rosdep/sources.list.d/20-default.list -o /etc/ros/rosdep/sources.list.d/20-default.list
export ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml
grep -qxF 'export ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml' ~/.bashrc || echo 'export ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml' >> ~/.bashrc
rosdep update
```



### 6\.3 配置终端环境

## 9 常见问题



|现象|先检查|处理|
|---|---|---|
|找不到 `ros-humble-desktop` 或 `ros-jazzy-desktop`|`lsb_release -sc` 是否分别为 `jammy` 或 `noble`|检查 `/etc/apt/sources.list.d/ros2.list` 是否为第 6\.1 节对应版本的清华地址，再运行 `sudo apt update`|
|`ros2: command not found`|`echo $ROS_DISTRO`|按系统版本执行第 6\.3 节的 `source` 命令|
|`rosdep update` 下载失败|`echo $ROSDISTRO_INDEX_URL` 是否显示清华地址|重新执行第 6\.2 节的镜像配置命令，再运行 `rosdep update`|
|`apt` 或 `curl` 下载失败|系统时间、网络与代理|保留完整报错，换稳定网络后重试；不要添加未知软件源|
|安装器只显示擦除磁盘|是否需要保留原系统|退出安装器并使用 Try Ubuntu；不要进入手动分区|
|安装器提示 BitLocker 或看不到内置硬盘|Windows 是否启用了磁盘加密，或安装器是否提示 Intel RST/VMD|停止安装，按第 2\.2 和 3\.4 节检查；不要直接修改 BIOS/UEFI 存储设置|
