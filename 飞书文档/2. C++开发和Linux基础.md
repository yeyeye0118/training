## 1\. 认识终端和路径



在 Ubuntu 中按 `Ctrl + Alt + T` 打开终端。终端会显示一行提示符，光标后面是你输入命令的位置；下面代码块中的命令不包括提示符，逐行输入并按 `Enter` 即可。先运行：



```Bash
cd ~
pwd
ls
```



`cd ~` 回到你的个人目录，`pwd` 显示当前所在目录，结果通常类似 `/home/zhangsan`；`ls` 列出这里的文件和文件夹。Linux 的路径从根目录 `/` 开始，`/home/zhangsan` 是绝对路径；`~` 是当前用户个人目录的简写，`.` 是当前目录，`..` 是上一级目录。终端里的很多命令都作用于“当前目录”，因此每次找不到文件时，先用 `pwd` 和 `ls` 确认自己在哪儿、文件是否真的在这里。



现在创建练习文件夹，并用 VS Code 打开：



```Bash
mkdir -p ~/venom_cpp_basics
cd ~/venom_cpp_basics
pwd
code .
```



`mkdir` 用于创建目录，`-p` 表示目录已存在时也可以继续执行。`code .` 中的 `.` 代表当前目录，整条命令会用 VS Code 打开它。此时 `pwd` 应显示 `/home/你的用户名/venom_cpp_basics`。以后编译这个文件夹中的程序时，先在终端进入该目录；也可以通过 VS Code 顶部菜单 `Terminal → New Terminal` 打开终端。



常用操作先记住这几个：`cd 目录名` 进入子目录，`cd ..` 返回上一级，`cd ~` 返回个人目录，`ls` 查看当前目录，按 `Tab` 补全文件名，按键盘上的向上方向键找回上一条命令。输入时注意大小写：`Direction.cpp` 和 `direction.cpp` 是两个不同的文件名。在个人目录下编写和编译程序不需要 `sudo`；安装软件时才会用到它。



## 2\. 这些开发工具各管什么



写好 C\+\+ 代码后，还要编译才能运行；程序出问题时，可以用调试器查看原因。这些工具各有用途：



|工具|本篇中的作用|
|---|---|
|VS Code|编辑 `direction.cpp`、打开终端、设置断点；它本身不是 C\+\+ 编译器。|
|`g++`|把 C\+\+ 源代码编译成可运行的程序。|
|CMake|读取 `CMakeLists.txt`，生成构建规则；它不是编译器。|
|Ninja|按 CMake 生成的规则调用 `g++`，完成构建。|
|GDB|在断点处暂停程序、查看变量；本篇通过 VS Code 使用它。|
|Git|保存代码的修改历史，便于以后协作。|



在终端输入 `g++ --version`、`cmake --version`、`ninja --version` 和 `gdb --version`，确认这些工具已经安装。版本号不必和别人的完全相同；如果出现 `command not found`，回到安装指南的工具链安装部分检查。



## 3\. C\+\+ 代码怎样变成程序



`.cpp` 是你写的源代码。它变成可运行的程序，大致经过以下步骤：



`源代码 .cpp → 编译为目标文件 .o → 链接为可执行程序 → 运行`



目标文件 `.o` 是编译过程中产生的文件，不能直接运行；链接会把它和程序用到的库组合起来。输入 `g++ direction.cpp -o direction` 时，`g++` 会完成这些步骤，生成可运行的 `direction`。



## 4\. 写一个有输入和判断的 C\+\+ 程序



在 VS Code 左侧文件列表中新建 `direction.cpp`，粘贴以下代码并保存。输入的数字表示目标相对中心的水平偏差：负数表示偏左，正数表示偏右；偏差在 `-10` 到 `10` 之间（包括两端）仍算居中。



```C++
#include <iostream>

int classify_offset(int offset) {
    if (offset < -10) {
        return -1;
    }
    if (offset > 10) {
        return 1;
    }
    return 0;
}

int main() {
    int offset = 0;
    std::cout << "输入目标相对中心的水平偏差（整数，左负右正）：";
    if (!(std::cin >> offset)) {
        std::cerr << "请输入整数\n";
        return 1;
    }

    int direction = classify_offset(offset);
    if (direction == -1) {
        std::cout << "目标偏左\n";
    } else if (direction == 1) {
        std::cout << "目标偏右\n";
    } else {
        std::cout << "目标居中\n";
    }
    return 0;
}
```



程序从 `main` 开始执行。`std::cin` 读取你输入的整数并存入 `offset`；如果输入不是整数，程序报错并结束。`classify_offset` 根据这个数返回 `-1`、`0` 或 `1`，后面的 `if / else if / else` 再决定输出“偏左”“居中”还是“偏右”。`#include <iostream>` 提供输入输出功能；`std::cout` 输出结果，`std::cerr` 输出错误。复制代码时不要漏掉分号和括号。



## 5\. 编译、运行，再修改



先用 `pwd` 确认当前位于练习目录，再用 `ls` 确认能看到 `direction.cpp`，然后编译并运行：



```Bash
pwd
ls
g++ -std=c++17 -Wall -Wextra -g direction.cpp -o direction
./direction
```



`direction.cpp` 是源代码，`g++` 将它编译成名为 `direction` 的可执行程序；`-std=c++17` 指定 C\+\+ 版本，`-Wall -Wextra` 启用常见警告，`-g` 保留调试所需的信息。编译成功通常没有输出。`./direction` 用来运行程序，`./` 表示程序位于当前目录。



程序提示输入时，键入 `-30` 并按 `Enter`，应看到“目标偏左”。再次运行并输入 `0`，应看到“目标居中”；输入 `25`，应看到“目标偏右”；输入 `abc`，应看到“请输入整数”。



试着把代码里两处判断用的 `10` 都改成 `20`，保存后再运行一次编译命令。此时输入 `15` 应看到“目标居中”，输入 `21` 应看到“目标偏右”。**每次修改源代码后都要重新编译**，否则运行的还是旧程序。



## 6\. 用 CMake 管理构建



只有一个源文件时，直接用 `g++` 编译很方便。源文件多了，可以用 CMake 统一管理要编译的文件和编译选项：CMake 读取 `CMakeLists.txt` 并生成构建规则，Ninja 再按规则调用 `g++`。顺序是 `CMakeLists.txt → CMake → Ninja → g++ → 程序`。



在 `~/venom_cpp_basics` 中新建文件，名字必须是 `CMakeLists.txt`，填入以下内容并保存：



```CMake
cmake_minimum_required(VERSION 3.16)
project(venom_cpp_basics LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(direction direction.cpp)
target_compile_options(direction PRIVATE -Wall -Wextra)
```



前两行写明 CMake 的最低版本和项目名称；中间两行指定 C\+\+17；`add_executable` 指定把 `direction.cpp` 编译成 `direction`；最后一行让编译器显示更多警告。



保存 `direction.cpp` 和 `CMakeLists.txt`，在练习目录中运行：



```Bash
cd ~/venom_cpp_basics
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/direction
```



`cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug` 会在 `build` 文件夹生成编译所需的文件，`Debug` 表示保留断点调试所需的信息。`cmake --build build` 编译程序，`./build/direction` 运行编译结果。它和前面手动编译得到的 `./direction` 是两个文件，运行时要看清路径。修改 `.cpp` 后，保存并重新执行 `cmake --build build`；修改 `CMakeLists.txt` 后，先重新运行上面的第一条 `cmake` 命令，再编译。



## 7\. 用断点看程序如何判断



在 VS Code 中打开 `direction.cpp`，点击 `if (direction == -1)` 这一行左侧的空白处；出现红点就表示断点已设好。按 `F5`，初次调试时选择 `C/C++: g++ build and debug active file`；如果先出现环境选择，再选 `C++ (GDB/LLDB)`。程序在终端提示输入后，输入 `-30`。



程序停在断点处时，左侧 `Variables` 区域应显示 `offset` 为 `-30`、`direction` 为 `-1`。按 `F10` 单步执行，看看程序进入哪个分支；按 `F5` 继续运行到结束。



如果程序没有在断点处暂停，先确认已经保存 `direction.cpp`，并且调试的是这个文件；手动编译时，还要确保命令中带有 `-g`。



## 8\. Git 与 GitHub



建议先阅读[菜鸟教程：Git 教程](https://www.runoob.com/git/git-tutorial.html)中的“Git 工作流程”“Git 工作区、暂存区和版本库”“Git 基本操作”“Git Github”四篇。后面遇到看不懂的概念或命令，再回去查对应章节。



Git 是一种版本控制系统，用来记录代码的修改过程。你修改程序、按下保存键，只是改变了当前文件；Git 不会自动把每次保存都记成一个版本。要留下一个以后能查看的版本，需要选中这次改动的文件，创建一次“提交”（commit），并写明改了什么。以后可以查看每次提交的内容，查清问题是从哪次修改开始的。



GitHub 是存放 Git 仓库的网站，与电脑上的 Git 不是同一个东西。即使没有网络，你也可以先在本机创建提交；只有把提交推送到 GitHub，网页上的仓库才会更新，其他人才能看到你的修改。



### 8\.1 确认身份和登录方式



先运行 `git --version`，确认 Git 已安装。安装指南中已经设置过提交时使用的名称和邮箱；用下面两条命令检查。它们查看的是提交记录上的信息，**不是 GitHub 登录状态**。公开仓库中的提交邮箱可能被别人看到。如果不想公开真实邮箱，可以在 [GitHub 邮箱设置说明](https://docs.github.com/en/account-and-profile/concepts/email-addresses)中查找 GitHub 提供的专用邮箱地址。



```Bash
git config --global --get user.name
git config --global --get user.email
```



如果其中一项没有输出，或需要修改，就把下面对应命令的示例值换成自己的名称或邮箱后再运行：



```Bash
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```



要把代码推送到 GitHub，还需要登录。第一次从这台 Ubuntu 电脑推送时，安装 GitHub 命令行工具 `gh`，并按终端提示在浏览器中完成登录。如果终端显示一次性验证码，就按提示到 GitHub 页面输入并授权；不要把验证码或登录凭据发给别人。



```Bash
sudo apt install -y gh
gh auth login -h github.com -p https --web
gh auth setup-git
gh auth status
```



### 8\.2 Fork 并克隆培训仓库



没有 GitHub 账号的话，先在 [GitHub](https://github.com/) 注册并登录。打开 [Venom 算法组培训仓库](https://github.com/Venom-Algorithm/training)，点击 **Fork**，把仓库复制到自己的账号下，仓库名保持 `training`。然后在自己仓库的页面点击 **Code → HTTPS**，复制地址。下面命令里的 `USERNAME` 要换成自己的 GitHub 用户名；如果电脑上已经有 `~/venom_cpp_basics/training`，直接进入该目录，不要再次运行 `git clone`。



```Bash
mkdir -p ~/venom_cpp_basics
cd ~/venom_cpp_basics
git clone https://github.com/USERNAME/training.git
cd training
git remote -v
git branch --show-current
git status
```



克隆完成后，`training` 文件夹里会有隐藏的 `.git` 目录，用来保存版本记录，所以不需要再运行 `git init`。`git remote -v` 显示的 `origin` 应是你自己 Fork 的地址；`git branch --show-current` 应显示 `main`，后面的命令都在这个分支上执行。



`git status` 用来查看哪些文件已修改、哪些文件已选中准备提交。刚克隆完成时，通常会显示没有待提交的改动。如果 Git 提示 `not a git repository`，先运行 `pwd`，确认自己在 `training` 或它的子目录中。



### 8\.3 修改、暂存、提交、推送



修好作业并通过测试后，回到仓库根目录执行以下命令。`git diff` 显示文件改了什么；`git add` 选中这次要提交的源文件；`git diff --cached` 显示选中后将要提交的内容。编译生成的程序不需要提交，作业目录中的 `.gitignore` 已让 Git 忽略它们。



如果误选了别的文件，可以用 `git restore --staged 文件路径` 取消选中；这不会删除文件或你写的内容。



```Bash
cd ~/venom_cpp_basics/training
git status
git diff -- 01-first-assignment/password_checker.cpp
git add 01-first-assignment/password_checker.cpp
git diff --cached
git commit -m "Fix password checker"
git log -1 --oneline
git push origin main
git status
```



`git commit` 只把修改记录在电脑上；运行 `git push origin main` 后，提交才会出现在你自己的 Fork 中。推送后打开 `https://github.com/USERNAME/training`，确认能看到修改后的文件和最新提交，再把这个仓库链接用于提交作业。以后做新作业时，按同样的步骤操作，只需把 `git add` 后面的路径换成新作业要求提交的文件。



想进一步了解命令，可以查阅 [Git 官方教程](https://git-scm.com/book/zh/v2/Git-%E5%9F%BA%E7%A1%80-%E8%AE%B0%E5%BD%95%E6%AF%8F%E6%AC%A1%E6%9B%B4%E6%96%B0%E5%88%B0%E4%BB%93%E5%BA%93)。不要把真实密码、密钥或登录验证码写进仓库。



### 8\.4 以后新增作业时同步



假设你完成第一次作业后，算法组在培训仓库里新增了“第二次作业”文件夹。你之前 Fork 的仓库不会自动出现这个文件夹，电脑上的仓库也不会。要拿到新作业，需要把算法组的新内容取到电脑上，再上传到自己的 Fork；不用重新 Fork 或克隆。



你的电脑需要记住两个仓库地址：`origin` 是你自己的 Fork，克隆时已经设置好了；`upstream` 是算法组的培训仓库，需要添加一次。先运行 `git remote -v` 检查。如果已经显示 `upstream`，就跳过 `git remote add upstream`。



```Bash
cd ~/venom_cpp_basics/training
git remote -v
git remote add upstream https://github.com/Venom-Algorithm/training.git
```



算法组以后每次发布新作业时，都在本地仓库运行下面的命令。先看 `git status`：如果有未提交的修改，先按 8\.3 节提交，再继续。



```Bash
cd ~/venom_cpp_basics/training
git status
git fetch upstream
git merge --no-edit upstream/main
git push origin main
```



`git fetch upstream` 下载算法组的新内容，但暂时不改动你的文件。`git merge --no-edit upstream/main` 把下载的更新并入电脑上的仓库，新作业文件夹这时才会出现。最后，`git push origin main` 把更新上传到你自己的 Fork。



如果 `git merge` 提示冲突，先不要运行后面的 `git push`，更不要强制推送。遇到任何 Git 报错，都可以把运行的命令、完整报错和 `git status` 的输出发给 AI，并说明你想做什么，让它针对当前情况指导你处理。

## 10\. 遇到问题先这样检查



|现象|检查方法|
|---|---|
|`direction.cpp: No such file or directory`|运行 `pwd`、`ls`，确认进入了 `~/venom_cpp_basics`，并核对文件名（包括大小写）。|
|编译提示 `expected ';'` 或 `expected '}'`|看报错中的文件名、行号和前后几行，检查分号与括号；修正并保存后重新编译。|
|改了代码但结果没变|重新编译改过的源文件，再运行刚编译出的程序。|
|`cmake` 找不到 `CMakeLists.txt`|运行 `pwd`、`ls`，确认当前目录里有这个文件，并从该目录执行 CMake 命令。|
|CMake 提示找不到 Ninja|用 `ninja --version` 检查工具；缺失时回到安装指南的工具链安装部分。|
|`./direction` 与 `./build/direction` 结果不同|这是两个不同的可执行文件。修改代码后，确认你运行的是刚编译的那个。|
|输入后没有出现结果|确认是在程序等待输入的终端里键入，并按了 `Enter`；若要结束正在运行的程序，按 `Ctrl + C`。|
|VS Code 断点没有停住|检查断点是否为红点、是否选中了正确的源文件，以及编译命令是否带 `-g`。|
